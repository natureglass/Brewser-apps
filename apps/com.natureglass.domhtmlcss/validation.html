Form validation enforcement

Constraint validation now runs when a submit button is tapped. The form below uses a GET action to two.html, so a successful submit visibly navigates to the “two” page, while a blocked submit stays here. The form sits in a scrollable box — filled inputs must scroll cleanly with no pinned “ghost” duplicates.

Expected behaviour

1. Tap Submit with fields empty/invalid → navigation is blocked (you stay on this page) and the form scrolls to the first invalid field.

2. Fill every field correctly, then Submit → navigates to two.html with the values in the query string.

3. Skip validation (a formnovalidate button) → always navigates, even when empty.

4. Reset → clears every field back to its default.

Plan (required radio)

The last fields sit below the fold of this scroll box on purpose — an invalid one further down should scroll into view.
