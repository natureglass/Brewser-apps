POST request bodies

A <form method="post"> submit now sends the fields as an application/x-www-form-urlencoded request body (previously POST navigated to the action with no body). GET is unchanged (fields go in the query string).

Note on testing

Citron has no network, so a real echo of the body needs hardware. The local test below proves the whole pipeline runs and navigates with the body attached; a static local file just can't show it back.

To confirm the exact bytes sent, enable navDebug in config.json and read sdmc:/switch/brewser/logs/shell-nav-diag.log — it logs method=POST and the body length.

1. Local POST (works on Citron)

Posts to a local page. It navigates to the “two” page without crashing; the body is sent but the static file ignores it.

2. Echo POST (needs internet — hardware only)

Posts to httpbin.org/post, which echoes the request. The JSON response now renders as a text page, so on hardware you should see your submitted fields back under "form" — the real end-to-end proof that the body was sent.

3. GET for comparison (unchanged)

Same fields via GET — they land in the two.html?… query string.
